# pi-zentao 0.4.0 设计：对照 zentao-cli 0.3.x 重构

日期：2026-09-23
状态：已获批准（对话确认）
基线：`zentao-cli ^0.3.1`（依赖已升级，0.2.0 → 0.3.1 调用契约实测兼容）

## 背景与动机

zentao-cli 升级 0.3.x 后带来一批新能力：26 模块 / 229 操作、本地数据处理
（`--pick`/`--filter`/`--sort`/`--search`/`--limit`）、`--data` JSON 请求体、
调用前版本兼容检查（错误码 2010）、`my` 地盘模块（一次调用取"我的 Bug/任务/待办"）。

本项目（pi 插件）当前是 19 模块白名单 + 平铺字段写入 + 全量扫描式聚合，
存在：LLM 拉全量数据自过滤（上下文浪费）、嵌套对象写不了、me 视图靠
N×M 次扫描、若干 workaround。本设计对照新 CLI 全面重构，提升两侧易用性。

### 关键事实（已实测验证）

- 隐式列表、`--recPerPage`、JSON 信封 `{status,data,error}`、`profile` 形状、
  `login --useEnv` 在 0.3.1 下全部不变。
- `issue`/`risk`/`meeting`：无 scope 全局列表；`projectX --projectID=N`（必填）、
  `executionX --executionID=N`（必填）为范围变体。
- `feedback`/`ticket`/`system`：列表 scope 为 `--productID`。
- `todo`：仅 props/create/update/delete，**无 list**。
- `doc`/`my`：操作是扩展型（myDocs/projectIssues/my todos…），非 CRUD。
- `my` 模块要求服务器 22.5 / biz13.5 / max8.5 / ipd5.5；**当前目标服务器为
  22.0，调用报 2010** —— 所有依赖新能力的路径必须优雅降级。
- `get project <id>` 报 2005（禅道 API 无 project 详情接口），
  现有 `--search` + 客户端匹配的 workaround **必须保留**。
- `get execution <id>` 可用；任务排序可用原生 `--sort=id:desc` 替代
  `--params {"orderBy":"id_desc"}` hack。
- 版本/服务端错误码无 E 前缀（如 `2010`、`2005`）；客户端错误码仍带 E 前缀
  （E1001/E1004/E1006 等，`hintOf` 现有映射继续有效）。

## 目标 / 非目标

目标：
- LLM 工具侧：`--pick`/`--filter`/`--sort`/`--search`/`--limit` 透传、`--data`
  嵌套写入、模块白名单扩至 24、2010 友好提示。
- 人类侧：新模块语义化命令、现有命令参数化、me 视图并入待办。
- 清理：任务排序 hack 替换为原生 `--sort`；保留 project 详情 workaround 并补注释。

非目标（明确不做）：
- `doc`/`my` 不进通用 LLM 工具（避免 229 操作的复杂度进入工具描述）。
- 概览面板不加按产品/项目筛选参数（`zentao.config.json` 上下文已覆盖）。
- 不实现 CLI 侧"工作区管理"（CLI 自身待实现特性）。

## 设计

### 1. 版本基线与总体架构

- `package.json`：`zentao-cli ^0.3.1`（已改）；插件版本 0.3.0 → 0.4.0。
- 架构保持不变：`lib/cli.ts`（子进程执行 + JSON 信封解析）→ `lib/schema.ts`
  （模块白名单 + CLI 参数构造）→ `tools/`（LLM 工具）/ `commands.ts`（斜杠命令）
  / `lib/overview.ts`（聚合）/ `ui.ts`（渲染）。

### 2. LLM 工具 `zentao` 增强（src/tools/zentao.ts + src/lib/schema.ts）

新增可选入参（list/get 时由 schema 拼接到 CLI 参数；CLI 在不支持的操作上
会忽略或报错，透传即可）：

| 参数 | 类型 | CLI 形式 |
|---|---|---|
| `pick` | string（逗号分隔字段） | `--pick=a,b,c` |
| `filter` | string 或 string[] | 每个元素 `--filter=expr`（元素内逗号=AND，多次=OR） |
| `sort` | string | `--sort=pri:asc`（兼容旧 `pri_asc` 由 CLI 处理） |
| `search` + `searchFields` | string | `--search=kw` `--search-fields=f1,f2` |
| `limit` | number | `--limit=N` |
| `data` | string（JSON） | `--data=<json>`（嵌套对象/数组/长文本写入；与平铺 `fields` 并存，冲突时以 data 为准——CLI 行为，文档中注明） |

模块白名单 19 → 24，新增条目（`MODULE_INFO`）：

| 模块 | scopeFlag | list 映射 |
|---|---|---|
| `issue` | null（scopeOptional 语义改造） | 有 `project` → `[issue, projectIssues, --projectID=N]`；有 `executionID` → `[issue, executionIssues, --executionID=N]`；皆无 → `[issue]` 全局列表 |
| `risk` | 同上 | `projectRisks` / `executionRisks` / 全局 |
| `meeting` | 同上 | `projectMeetings` / `executionMeetings` / 全局 |
| `todo` | 无 scope；actions 仅 create/update/delete | 不涉及 list |

实现方式：`ModuleInfo` 增加可选 `scopedList?: { projectOp: string; executionOp: string }`，
`buildCliArgs` 的 list 分支优先走 scopedList 映射。`feedback`/`ticket`/`system`
现有 `--productID` 映射经实测无误，不动。

工具描述（DESCRIPTION / promptGuidelines）更新：
- `--filter` 语法示例（`status=active,pri<=2`）与 AND/OR 语义。
- 版本不足时报 2010，提示换操作或升级服务器。
- 写入建议：嵌套/长文本用 `data`，简单字段用 `fields`。

### 3. `zentao_my_overview` 工具与面板（src/lib/overview.ts + tools/my-overview.ts）

me 视图双路径：
1. **快速路径**：`my bugs` + `my tasks`（+ 尝试 `my todos`）各一次调用。
   - `my todos` 报 2010 → 跳过待办，不报错。
   - `my bugs`/`my tasks` 报 2010 → 整体回退到现有扫描逻辑。
2. **回退路径**：现有 product×bug + project×execution×task 扫描，行为不变。

me 视图数据模型 `MyItem` 增加 `kind: "todo"`；`my todos` 成功时并入
（字段：id/title/status/date，pri 固定显示 `-`）。`ui.ts overviewLines`
相应增加 todo 行渲染。

project 视图：不变。

### 4. 斜杠命令（src/commands.ts）

新增（全部复用现有 `zentao-card` / detail 渲染器；版本不足时报友好提示）：

| 命令 | 实现 |
|---|---|
| `/zentao-todos` | `my todos`，2010 时提示"禅道 22.5+ 才支持" |
| `/zentao-docs [产品ID]` | 无参 → `doc myDocs`；有参 → `doc productDocs --productID=N --libID=?`……（注：productDocs 需 libID，见"待澄清风险"） |
| `/zentao-meetings [项目ID]` | 无参 → `meeting` 全局；有参 → `meeting projectMeetings --projectID=N` |
| `/zentao-risks [项目ID]` | 同上 pattern（`risk`/`projectRisks`） |
| `/zentao-issues [项目ID]` | 同上 pattern（`issue`/`projectIssues`） |

现有列表/详情命令参数化：`/zentao-products`、`/zentao-projects`、`/zentao-bug <id>`、
`/zentao-task <id>`、`/zentao-story <id>` 的 handler 解析 `--filter=`/`--sort=`/
`--pick=`/`--limit=` 并透传到 CLI 参数（复用 `splitArgs`，仅认可以上四个前缀，
其余参数照旧提示用法）。

D 项清理：
- `lib/overview.ts` scoped 任务排序：`--params {"orderBy":"id_desc"}` → `--sort=id:desc`。
- `commands.ts buildProjectDetailArgs`：保留 `--search` + 客户端精确匹配，
  注释说明"禅道 API 无 project 详情接口（get project → 2005），保留 workaround"。

### 5. 错误处理（src/lib/cli.ts `hintOf`）

新增 `2010`/`E2010` 映射："当前禅道版本过低，不支持该操作（最低要求见错误详情），
可升级禅道或改用其他操作"。其余映射不变。

### 6. 测试

新增/更新单测（全部 mock `RunFn`，不依赖真实服务器）：
- schema：`issue`/`risk`/`meeting` 三种 list 映射（project/execution/全局）、
  `todo` 动作白名单、`pick`/`filter`/`sort`/`search`/`limit`/`data` 透传、
  未知模块/动作报错文案。
- overview：my 快速路径成功合并 todo；`my todos` 2010 跳过；
  `my bugs` 2010 整体回退扫描路径（断言调用了 product/project 列表）。
- cli：`hintOf` 2010 映射。
- commands：新命令参数解析（`/zentao-issues 167` vs 无参；
  现有命令 `--filter`/`--sort` 透传）。

验收：`npm run verify`（typecheck + vitest）全绿；真实环境只读抽查
`/zentao-issues`、`/zentao-todos`（预期 2010 友好提示）。

## 风险与待澄清

- `/zentao-docs <产品ID>`：`doc productDocs` 需要 `--libID`（必填），产品下
  可能有多个文档库。实现时先 `doc productLibs --productID=N` 列出库，取首个
  或全部库汇总展示；若无库则提示。实现细节以 `zentao doc productDocs --help`
  实测为准。
- `my` 快速路径下 me 视图的 `scope` 字段（产品/执行名）：`my bugs` 返回中
  的 product 字段是 ID 或数组，名称展示降级为 `#id`，不做 N 次详情查询
  （快路径的意义就是少调用）。
- CLI 0.3.x 的 `--filter` 在 0.2.x 不存在；依赖已锁 ^0.3.1，无需兼容旧版。
